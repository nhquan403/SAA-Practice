1. Tool use: chọn tool, dispatcher & vòng lặp

  • Chọn tool là quá trình ngữ nghĩa: từ khóa trong system prompt trùng tên tool gây lệch → dấu hiệu đề "sau khi thêm một dòng prompt" → sửa câu chữ trung tính Q1
  • Claude lập kế hoạch ≠ dispatcher thực thi: API không chạy tool, không định thứ tự; read-only song song, tool có side effect tuần tự Q2
  • disable_parallel_tool_use: ép một tool call mỗi lượt → tuần tự hóa cả Grep/Read độc lập Q2
  • Vòng lặp Messages API trực tiếp: tool_use → gửi tool_result; end_turn → kết thúc; không có ResultMessage Q20
  • Turn cap: là giới hạn an toàn, chạm cap = run thất bại (SDK: error_max_turns), không phải đáp án Q20
  • pause_turn: thuộc vòng lặp server tool; gửi lại nội dung assistant, không gửi tool_result Q20
  • tool_choice ép tool ≠ extended thinking: any/tool + thinking thủ công → 400; cần bảo đảm call thì bỏ thinking Q43
  • strict: true: chỉ ép input khớp schema, không chọn tool, không sắp thứ tự Q2, Q43

2. Lỗi tool & error metadata (MCP)

  • isError: true ≠ JSON-RPC protocol error: lỗi thực thi (timeout, input sai) để model thấy; protocol error cho tool không tồn tại, host xử lý Q7, Q13
  • Error text là tín hiệu phục hồi duy nhất: "Operation failed" → model lặp lại; nêu nguyên nhân + định dạng mong đợi Q7, Q17
  • Timeout ≠ kết quả rỗng: timeout gắn cờ lỗi + transient/retryable; danh sách rỗng vẫn là success Q13, Q26
  • Retry trong server: chỉ hợp lỗi chớp nhoáng; outage vài phút làm treo hội thoại; không trả empty success Q13, Q26
  • Phân loại lỗi: transient → retry y nguyên; validation → sửa input rồi retry; business/permission → giải thích/escalate Q17, Q25
  • Gán nhầm category: lỗi định dạng mà dán permission + không retry → agent escalate thừa Q25
  • Business denial retriable: false: chuyển tóm tắt chính sách cho khách, không gọi lại, không escalate Q16
  • Metadata ứng dụng ≠ field giao thức: errorCategory, isRetryable do team tự định nghĩa; MCP chỉ chuẩn hóa isError Q16, Q17, Q25

8. Trích xuất có cấu trúc, few-shot & Batch API

  • Schema hợp lệ ≠ giá trị đúng: schema ép hình dạng; lỗi ngữ nghĩa vẫn lọt Q36, Q37, Q40, Q45
  • Few-shot gần biên: false positive ở câu chữ lấp lửng → thay ví dụ rõ ràng bằng ví dụ sát ranh giới Q36
  • Few-shot đa dạng + rationale: nhiều layout khác nhau, giải thích vì sao gán field → khái quát layout mới Q40

  • XML tag: <example> trong <examples>, input trong <document> → hết rò giá trị ví dụ Q42
  • Enum + "other"/"unclear": chặn tên bịa, cho lối thoát trung thực, router vẫn nhận giá trị hợp lệ Q44
  • stated_total vs calculated_total: mâu thuẫn nằm trong tài liệu → đưa người review kèm cả hai Q37
  • Retry có feedback: chỉ sửa lỗi model; dữ kiện vắng khỏi input thì quay về tài liệu gốc Q37, Q38
  • Mất trích dẫn qua summary: kiểm quote có trên trang gốc + chạy lại trên hợp đồng gốc Q38
  • Batch lỗi invalid_request_error: theo custom_id, chia nhỏ tài liệu, gửi batch chỉ gồm request đã sửa Q39
  • Batch deadline: không SLA, tối đa 24 giờ, không stream → nộp ngay khi đủ dữ liệu Q41

9. Confidence, review, xung đột dữ liệu & escalation

  • Self-reported confidence ≠ xác suất hiệu chuẩn: đo accuracy theo dải trên mẫu có nhãn rồi mới đặt ngưỡng Q34, Q50, Q56
  • Đo error rate luồng tự động: mẫu ngẫu nhiên phân tầng hằng tuần, không đếm lỗi bị báo lại Q35
  • Đúng độ hạt: lỗi ở từng hàm/finding → điểm confidence theo từng mục, không theo cả changeset Q50, Q56
  • Tách tìm và lọc: báo mọi finding kèm confidence, lọc downstream bằng ngưỡng chỉnh được Q56
  • Flag sai 70%: biết nguyên nhân hẹp → viết tiêu chí rõ (định dạng ngày hợp lệ); mất niềm tin lan sang flag khác Q32
  • Pass tổng hợp: chỉ kiểm nhất quán chéo, nhận kết quả từng phần để không lặp Q33
  • Hai nguồn đáng tin mâu thuẫn: giữ cả hai có nguồn + ngày đo, đánh dấu cho người review Q51
  • Giận dữ ≠ cần người: ghi nhận cảm xúc rồi giải quyết; yêu cầu người rõ ràng → escalate ngay, không tra cứu Q18, Q59
  • Trigger escalate: khách đòi người, chính sách mơ hồ/thiếu, không tiến triển được Q16, Q18, Q59

13. Mẹo làm bài thi

  • Tìm "dữ kiện quyết định": mỗi đáp án sai là kỹ thuật thật nhưng vấp một chi tiết đề nêu (dòng thời gian, unattended, ngân sách 1 request).
  • Hỏi "ai cần hành động?": model cần sửa → kênh model thấy; host cần xử lý → protocol error.
  • Ép buộc thì dùng code: hook, schema, permission; prompt chỉ là xác suất.
  • Đúng thời điểm vòng đời: chặn trước (PreToolUse), đổi kết quả sau (PostToolUse); review sau không ngăn được.
  • Hỏi "context nào nhìn thấy gì?": subagent, fork, session, context: fork khác nhau ở thứ được mang theo.
  • "Select two" là hai nửa bổ trợ: Glob + Grep Q19, kiểm quote + về tài liệu gốc Q38, enum + unclear Q44, giữ cả hai số + ngày đo Q51.
  • Sửa đúng gốc, cân xứng: một file đổi thì đọc lại một file, không bỏ cả session.
  • Confidence chỉ dùng được khi: đúng độ hạt và đã hiệu chuẩn trên dữ liệu có nhãn.
