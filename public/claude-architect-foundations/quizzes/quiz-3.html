1. Claude Code: scope cấu hình, memory, rules, skill & command

  • Vị trí file = ranh giới chia sẻ: trong repo (.mcp.json, .claude/) cho team; ~/.claude* cá nhân, không vào git Q1, Q22
  • MCP scope user: ~/.claude.json, riêng máy, mọi project → dấu hiệu đề "prototype riêng, nhiều project" Q1
  • MCP precedence: local → project → user, không merge; ~/.claude/settings.json chỉ chứa permission, hook Q1
  • CLAUDE.md thư mục con: nối thêm vào root, nạp khi chạm file trong thư mục → "quy ước riêng một package" Q16
  • @path import: đường dẫn tương đối tính từ file chứa import, không từ working dir Q26
  • Rule có paths ≠ nạp lúc khởi động: chỉ nạp khi Read/Write/Edit file khớp; cần có từ đầu → bỏ paths Q24, Q29
  • Glob rule: tính từ thư mục chứa .claude; paths nhận YAML list hoặc chuỗi phẩy; quét đệ quy Q24, Q29
  • Command dùng chung: chuyển vào .claude/commands/ rồi commit; skill ở ~ vẫn cá nhân Q22
  • Skill allowed-tools: pre-approve theo turn, scoped như Bash(npm run *); văn bản SKILL.md không tắt prompt Q20
  • argument-hint: hiện tham số khi autocomplete → "gõ lệnh trống, ra output chung chung" Q21
  • Plan mode: cho việc mơ hồ, nhiều file, code lạ; diff mô tả một câu thì làm thẳng Q31

2. Workflow hay agent, agent loop & chọn tool

  • Bước biết trước ≠ agent: chuỗi cố định → code path; việc mơ hồ giữ model-driven loop Q3
  • Kết thúc loop: chạy khi stop_reason = tool_use, dừng khi end_turn; không dò câu chữ Q38
  • max_turns: rào an toàn, chạm trần ra error_max_turns, không định nghĩa "xong" Q3, Q38
  • Description tool = tín hiệu chọn chính: nêu format tham số, ví dụ, khi nào dùng/không dùng, edge case Q8, Q15, Q43, Q44
  • Tool trùng tên/mô tả: đổi tên theo nguồn + ghi ranh giới áp dụng → "gọi nhầm tool" Q44
  • Escalation: bực bội không phải trigger; yêu cầu gặp người, policy gap, kẹt tiến độ mới là trigger Q15
  • "CRITICAL: MUST": gây overtrigger trên model mới; viết thường "Use X when…" Q17
  • tool_choice theo từng request: ép tool lượt đầu, lượt sau trả về auto Q49
  • Prompt giao việc: mô tả mục tiêu + tiêu chí chất lượng, không kịch bản bước cho việc khám phá Q28
  • Ví dụ là kiểm chứng: model hardcode theo mẫu → yêu cầu lời giải tổng quát, mẫu chỉ để test Q23

3. Subagent: AgentDefinition, context isolation & coordinator

  • description ≠ prompt: description để parent quyết định giao việc; prompt là system prompt của subagent Q4, Q33
  • tools là allowlist: bỏ trống thì thừa hưởng mọi tool; loại tool nguy hiểm là bảo đảm cấu trúc Q4, Q9, Q43
  • Subagent thường ≠ thấy history: chỉ nhận delegation prompt; phải đưa tóm tắt + danh sách nguồn vào prompt Q5, Q41
  • Fork: ngoại lệ duy nhất, copy hội thoại parent; tốn token, mất isolation → "cần toàn bộ hội thoại" Q5
  • initialPrompt: chỉ chạy khi agent là main thread; bị bỏ qua khi gọi làm subagent Q41
  • Explore subagent: read-only, context riêng, chỉ trả tóm tắt → "kết quả Grep tràn context" Q30
  • Hub-and-spoke: coordinator là relay duy nhất → quan sát được, xử lý lỗi thống nhất Q37
  • Độ phủ đặt ở bước phân rã: coordinator map toàn bộ phạm vi rồi chia subtask không chồng lấn Q46
  • Đừng lạm dụng subagent: tìm kiếm đơn giản thì Grep trực tiếp Q39, Q31

4. Hook & kiểm soát tất định

  • Hook ≠ prompt: luật tài chính, pháp lý, thứ tự bắt buộc → PreToolUse deny; prompt chỉ xác suất Q13, Q32, Q34
  • Ưu tiên quyết định: deny → defer → ask → allow; hook allow mới không phá deny cũ Q13
  • Async hook output: chỉ cho log, metric; không chặn/sửa được → hợp audit log Q13, Q34
  • PostToolUse: chạy sau khi tool đã thực thi, không ngăn được hành động Q13, Q34
  • Chặn spawn sai thứ tự: hook trên tool Task từ chối report khi chưa có synthesis Q32
  • Matcher phải phủ mọi đường: hook một tool chỉ đủ khi đó là đường truy xuất duy nhất Q34
  • SessionStart: chạy khi start/resume; trả additionalContext liệt kê file đổi Q42
  • Hook không cho sai vấn đề: keyword gate, classifier là over-engineering khi lỗi nằm ở description/wording Q15, Q17

5. Session: resume, continue, fork & trạng thái cũ

  • Session = transcript ≠ snapshot filesystem/backend: resume trả lại file đọc cũ nguyên văn Q6, Q42
  • Đổi ít: resume + tham chiếu @ file đã đổi để đọc lại Q6
  • Đổi nhiều: session mới + tóm tắt có cấu trúc + danh sách file đổi Q6, Q42
  • resume ≠ continue: resume theo session ID; continue lấy session mới nhất → sai khách trên host chung Q14
  • Context còn đúng: resume bằng session_id lấy từ result message Q14
  • fork_session: ID mới, copy rồi tách; không hoàn tác side effect → chạy trên staging Q7
  • Session đã kết thúc: vẫn resume/fork được nếu còn transcript Q7
  • Crash pipeline dài: lưu state có cấu trúc + manifest, nạp vào prompt subagent kế Q45

6. Built-in tool: Read, Write, Edit, Grep

  • Write ≠ Edit: Write ghi đè toàn file, không merge; Edit thay chuỗi khớp duy nhất Q10, Q40
  • Đọc trước khi ghi: điều kiện quyền, không biến Write thành merge Q10
  • Anchor không duy nhất: mở rộng ngữ cảnh; vẫn trùng → Read toàn file rồi Write Q40
  • replace_all: chỉ khi mọi chỗ đều phải đổi Q40
  • Bash/sed: chỉ khi tool chuyên dụng không làm được Q10, Q40
  • Trace qua wrapper: Grep tên wrapper, Read file gọi nó, lặp đến call site thật Q39

7. Provenance, handoff & ngữ nghĩa lỗi của tool

  • Provenance được giữ, không tái dựng: mỗi finding đi cùng nguồn (record, điều khoản, trang) dưới dạng dữ liệu Q11, Q35
  • Ghi vị trí ở nơi đọc nguồn: subagent phân tích trả trích dẫn + trang/mục Q35
  • Compaction mất liên kết: yêu cầu summary giữ fact gắn order ID và kết quả lookup Q12
  • Handoff cho người: tự đủ — định danh, root cause, lỗi cụ thể, đề xuất Q25
  • Rỗng hợp lệ ≠ lỗi truy cập: không tìm thấy là kết quả thành công; lỗi dùng isError + retryable Q27, Q36, Q8
  • Kết quả rỗng là phát hiện: mở rộng query hoặc ghi chú coverage gap, không retry y nguyên Q36
  • Retry/backoff: chỉ cho lỗi tạm thời như timeout Q8, Q36

8. Structured output & schema cho extraction

  • Schema = hình dạng ≠ ý nghĩa: strict: true bảo đảm kiểu, field bắt buộc; ngày đảo, tổng sai vẫn lọt Q50, Q54
  • Validation-retry: kiểm business rule trong code, gửi lại lỗi cụ thể + tài liệu gốc Q50
  • Required ép bịa: field có thể thiếu → nullable (["string","null"]) + dặn trả null Q51, Q56, Q60
  • Retry không tạo ra dữ liệu thiếu: mỗi lần một số khác → bịa; route sang lookup/người Q60
  • minimum/maximum: không hỗ trợ, có thể 400; quy tắc chuẩn hóa để trong prompt/description Q55
  • Nội dung field không nhất quán: 2–4 few-shot example đầy đủ Q57
  • Print mode: --output-format json chỉ là vỏ; --json-schema → đọc structured_output Q18, Q19
  • CI an toàn: kiểm subtype success + có structured_output; lỗi error_max_structured_output_retries Q19

13. Mẹo làm bài thi

  • Loại ngay "self-rated confidence": xuất hiện gần như mọi câu và luôn sai; model tự tin cả khi sai.
  • "Guarantee" là từ khóa: chọn cơ chế chạy bằng code (hook, allowlist, schema), loại prompt nhấn mạnh.
  • Sửa tại nguồn: lỗi chọn tool → sửa description; lỗi độ phủ → sửa phân rã; provenance → output contract.
  • "Select two" là hai lớp: description + allowlist Q43, tên + mô tả Q44, cắt + context editing Q47, prompt + validate code Q55.
  • Retry chỉ cho lỗi tạm thời hoặc sửa được từ nguồn: loại khi lỗi tất định hoặc dữ liệu vắng.
  • Nghi "to hơn": context lớn hơn, budget lớn hơn, max_tokens lớn hơn hiếm khi đúng.
  • Tỉ lệ cân xứng: việc nhỏ không cần plan mode, subagent, fork, classifier.

Học đáp án đúng chỉ giải được đúng câu đó. Hiểu vì sao từng đáp án sai lại sai giúp nhận diện được cả họ câu hỏi tương tự, kể cả khi đề đổi cách hỏi. Mỗi dòng dưới đây là một câu, liệt kê các đáp án sai và lý do sai thật sự — đúc kết từ chính phần giải thích của đề, không phải suy đoán.

CâuĐáp án sai & vì sao sai
Q1
  • Khai báo trong ~/.claude/settings.json: file này chứa permission và hook, không chứa đăng ký MCP server; MCP cá nhân nằm ở ~/.claude.json
  • Thêm vào .mcp.json của project: file này được commit và chia sẻ cả team, mọi người sẽ được hỏi approve một server thử nghiệm không ổn định
  • Mô tả tool trong CLAUDE.md: CLAUDE.md chỉ là ngữ cảnh, không kết nối được MCP server, lại còn được commit cho cả team
Q2
  • Thêm chỉ dẫn hạ confidence khi không chắc: lời dặn không làm confidence được calibrate; model vẫn tự tin khi sai, chỉ đo trên dữ liệu có nhãn mới biết
  • Gọi model thứ hai chấm lại confidence: hai lần tự chấm đồng ý vẫn là tự chấm, tốn thêm chi phí mà không trả lời độ chính xác từng segment
  • Nâng ngưỡng confidence chung cho mọi field: giả định confidence có nghĩa như nhau ở mọi field; giảm phần tự động mà không lộ ra segment nào đang hỏng
Q3
  • Đặt max_turns = 2 cho câu hỏi trạng thái: max_turns là trần an toàn, chạm trần kết thúc bằng lỗi; không quy định tool nào chạy hay thứ tự
  • Hard-code cây quyết định cho mọi loại request: returns và dispute có bước khác nhau, cây cố định gãy đúng ở ca mơ hồ và làm giảm first-contact resolution
  • Giữ mọi request trong loop, thêm luật thứ tự vào system prompt: prompt chỉ tăng xác suất, không cố định đường đi, và vẫn tốn suy luận mỗi lượt
Q4
  • Cấm process_refund trong prompt, để tools trống: bỏ trống tools thì subagent thừa hưởng mọi tool kể cả process_refund; prompt chỉ là tuân thủ xác suất
  • Bỏ field description vì coordinator đã truyền chi tiết: description là field bắt buộc và là thứ Claude đọc để quyết định giao việc; thiếu nó thì routing không ổn định
Q5
  • Truyền session ID của main agent trong prompt: không có cơ chế subagent tự gắn vào session cha qua ID; ID chỉ là chữ trong context rỗng
  • Compaction main agent trước: chỉ đổi context của main agent, subagent mới vẫn chỉ nhận prompt; lại còn rút hội thoại thành tóm tắt
  • Subagent thường tự chia sẻ history: subagent không fork bắt đầu context mới, không thấy hội thoại hay tool result của parent
Q6
  • Session mới, khám phá lại toàn repo: chỉ hai file đổi; bỏ hết phân tích hợp lệ của hôm qua, tốn token và thời gian
  • claude --continue rồi làm tiếp: resume khôi phục transcript, không đọc lại file từ đĩa; audit sẽ dựa trên nội dung policy cũ
Q7
  • Xem lại transcript production sau đó: hai session chỉ chung history đến điểm fork; lượt mới của fork không chảy về bản gốc
  • Phải fork trước khi session gốc kết thúc: session là transcript lưu đĩa, đã xong vẫn resume/fork được nếu còn transcript
Q8
  • Thêm luật system prompt chỉ truyền order ID hợp lệ: tín hiệu xa hơn description của tool, và không xử lý việc hiểu sai kết quả rỗng
  • Retry có backoff khi kết quả rỗng: coi kết quả rỗng hợp lệ là lỗi tạm thời; truy vấn không có kết quả sẽ rỗng mãi
Q9
  • Tự chấm confidence trước mỗi lần refund: self-rating không đáng tin, và subagent này không có ca refund hợp lệ nào để bảo vệ
  • Thêm helper select_tool chọn tool trước: thêm một bước chọn để giải bài toán chọn; helper vẫn có thể trả về process_refund vì tool còn trong scope
  • Luật system prompt cấm tự gọi process_refund: tool vẫn hiện diện và description vẫn mời gọi; với hành động tài chính, bỏ tool mạnh hơn dặn dò
Q10
  • Dặn luôn đưa toàn bộ notes vào mỗi lần Write: phụ thuộc model chép lại đúng toàn file mỗi lần, xác suất và tốn output
  • Dùng Bash nối dòng mới vào cuối file: giá trị cũ vẫn còn, notes thành mâu thuẫn; bỏ qua tool chuyên dụng
  • Read trước để Write tự merge: Write luôn ghi đè toàn file; đọc trước chỉ là điều kiện quyền, không biến thành merge
Q11
  • Cuối summary liệt kê mọi tool và tài liệu đã dùng: đó là danh mục tham khảo, không nói nguồn nào chứng minh kết luận nào
  • Bước handoff gắn nguồn "có khả năng nhất": tái dựng sau sự việc là đoán; trích dẫn sai còn tệ hơn không có vì tạo độ tin giả
  • Agent tự chấm confidence từng kết luận: model có thể tự tin khi sai, và con số không cho reviewer thứ gì để kiểm
Q12
  • Nâng ngưỡng compaction để tóm tắt muộn hơn: đổi thời điểm không đổi nội dung được giữ; tóm tắt muộn vẫn mất liên kết nguồn
  • Tự chấm confidence khớp order, thấp thì escalate: agent đã sai mà vẫn tự tin; điểm số không khôi phục liên kết fact với order
  • Dặn xác nhận order trước khi process_refund: sau compaction không còn thông tin order nào để xác nhận, chỉ xác nhận trên phỏng đoán
Q13
  • Chuyển kiểm tra cap sang PostToolUse: PostToolUse chạy sau khi refund đã thực thi, không ngăn được hành động
  • Ghi cap vào system prompt: tuân thủ xác suất; việc lệnh vượt cap có tới hook hay không phụ thuộc model, không phải enforcement
Q14
  • Session mới, chạy lại get_customer và lookup_order: context cũ còn đúng; làm lại tốn tool call, độ trễ và bỏ dữ liệu đã xác minh
  • Dùng continue mở session gần nhất: trên host chung, session gần nhất có thể của khách khác, gắn nhầm hội thoại
  • Session mới, dán toàn bộ transcript cũ: tái dựng thủ công, mất mát thứ SDK đã lưu sẵn, chiếm context bằng output dài
Q15
  • Thêm sentiment classifier với ngưỡng: tâm trạng không phản ánh việc agent có xử lý được không; vẫn giữ tiền đề sai là bực bội thì escalate
  • Hook chỉ cho escalate khi có chữ "human"/"manager": keyword gate giòn, chặn escalation hợp lệ diễn đạt khác hoặc policy gap
  • Tự chấm confidence giải quyết, thấp thì escalate: self-rating không calibrate, và description sai vẫn còn nguyên
Q16
  • Để trong root CLAUDE.md dưới heading billing: root nạp mọi session, tốn context cho package không liên quan và làm file chung dài, kém hiệu quả
  • Để trong ~/.claude/CLAUDE.md của từng dev: file cá nhân không qua git; người mới sẽ thiếu quy ước
  • Copy root CLAUDE.md vào billing rồi thêm luật: các file được nối với nhau, copy làm trùng nội dung và phải đồng bộ hai nơi
Q17
  • Giữ directive, thêm danh sách ngoại lệ: giữ nguyên câu lệnh gây overtrigger, phải vá thêm mỗi khi có loại lượt hội thoại mới
  • Đặt tool_choice = any: any buộc gọi tool mỗi lượt, làm hành vi tệ hơn
  • PreToolUse hook phân loại tin nhắn và chặn Grep: over-engineering cho vấn đề câu chữ; phân loại sai sẽ chặn cả tra cứu code hợp lệ
Q18

  • Thêm chỉ dẫn prompt phải là JSON đúng schema: chỉ tăng xác suất, đúng là lỗi đang gặp; pipeline không người giám sát cần kiểm tra thật

Q19

  • Vòng retry đến khi result parse được: chậm, tốn, không bảo đảm đủ field; --json-schema đã có validation, retry và subtype lỗi riêng

  • Điểm khẩn cấp và confidence tự chấm: mô tả thái độ của agent, không phải nội dung case; người nhận vẫn không hành động được

  • Đặt findings làm initialPrompt trong định nghĩa: initialPrompt chỉ tự gửi khi agent chạy main thread, bị bỏ qua khi là subagent
Q42
  • Resume rồi để agent tự chấm confidence phân tích cũ: agent không biết file đã refactor nếu không được báo hoặc đọc lại; self-rating không bù được
  • Resume nguyên trạng vì file tự refresh: session lưu history kể cả tool result cũ, không đọc lại file khi load
Q43
  • Luật chung luôn ưu tiên MCP tool: hướng dẫn xác suất, không sửa lý do tool kém hấp dẫn; còn đẩy dùng MCP cả khi built-in phù hợp hơn
  • Đổi thứ tự để MCP tool đứng trước Grep: vị trí trong danh sách không phải cơ chế chọn đáng tin; description vẫn mơ hồ
Q44
  • Thêm few-shot routing vào prompt coordinator: tốn token mỗi request, chỉ đẩy xác suất trong khi định nghĩa tool vẫn trùng
  • Thêm classifier tiền định tuyến: over-engineering bù cho lỗi định nghĩa tool, thêm thành phần phải bảo trì
Q45
  • Bọc pipeline trong retry tự chạy lại từ đầu: tự động hóa đúng vấn đề: chạy lại search đã xong và bỏ phân tích dở
  • Resume session coordinator để subagent tự tiếp tục: session là transcript của coordinator, không phải state pipeline; subagent không thừa hưởng nó
  • Tăng context budget để một lượt chạy hết: không ngăn crash, tiến độ vẫn nằm trong bộ nhớ và mất khi process chết
Q46
  • Dặn synthesis viết thêm mục cho vùng còn thiếu: không có findings nào về vùng đó; nội dung sẽ lấy từ kiến thức chung, không trích dẫn
  • Tăng giới hạn kết quả của web search: chỉ đào sâu các subtask hẹp đã giao, không thêm khu vực pháp lý chưa được hỏi
  • Cho synthesis context lớn hơn: synthesis không làm rơi findings; findings vùng khác chưa từng được tạo ra
Q47
  • Dặn model bỏ qua field không liên quan: field vẫn nằm trong context, vẫn tốn token và tranh chú ý mỗi lượt
  • Gắn cache_control cho kết quả vendor: caching giảm giá, nội dung cache vẫn chiếm đầy đủ context window
Q48
  • Cùng call tự phê bình rồi sửa confidence: vẫn trong ngữ cảnh suy luận đã tạo giá trị, model xu hướng xác nhận chính mình
  • Chạy ba lần, lấy trung bình confidence: giảm nhiễu ngẫu nhiên nhưng không sửa thiên lệch tự tin hệ thống; tốn gấp ba
  • Hạ ngưỡng, dưới 0.95 thì gửi người duyệt: field đúng và sai cùng trên 0.9, đổi ngưỡng không tách được chúng
Q49
  • Dặn system prompt chuyển sang enrichment: tool_choice ép tool là ràng buộc API, prompt không mở khóa được
  • Retry có error feedback khi không gọi enrichment: request ép tool cho cùng kết quả mọi lần, đây không phải lỗi tạm thời

Q50

  • Đặt strict: true: output đã đúng cấu trúc; lỗi là giá trị sai, schema không phát hiện được
  • Dặn model kiểm lại phép tính và vị trí field: có thể giảm lỗi nhưng không kiểm chứng; cần check tất định trong code
Q51

  • Thêm field confidence bắt buộc cạnh ngày: giữ nguyên giá trị bịa, bắt model tự chấm thứ nó bịa, lại thêm một field phải điền
  • Dặn system prompt không bịa ngày: schema strict vẫn đòi chuỗi; chỉ dẫn và schema mâu thuẫn, ràng buộc enforced thắng
Q52
  • Kiểm một mẫu ngẫu nhiên nhỏ từ production: mẫu đều bị loại tài liệu phổ biến chi phối, hiếm khi lộ loại hiếm lỗi cao
  • Bật strict schema, lỗi schema thì đưa người duyệt: chỉ bảo đảm cấu trúc, không nói giá trị có đúng hay không
  • Model tự chấm confidence, cao thì bỏ review: model có thể tự tin khi sai; confidence chưa calibrate không liên hệ tỉ lệ lỗi thật
Q53
  • Đổi model context window lớn hơn: packet đã vừa; vấn đề là chú ý dàn mỏng, không phải sức chứa
  • Thêm validation-retry gửi lỗi schema: output đã đúng schema; độ sâu thiếu và giá trị mâu thuẫn không có lỗi schema để gửi
  • Chạy ba lần, lấy giá trị khớp hai lần: lặp pass bị loãng chú ý, bỏ phát hiện thật chỉ xuất hiện một lần và che mâu thuẫn thu nhập

  • Giữ required, thêm chỉ dẫn cấm bịa: prompt và schema mâu thuẫn trực tiếp, model không có cách tuân thủ cả hai

  • Model tự chấm confidence từng flag: đo niềm tin về discrepancy, không đo việc tuân thủ quy ước; bỏ cả phát hiện thật
  • Viết lại description với lời lẽ mạnh hơn: thêm nhấn mạnh nhưng không thêm nội dung vận hành; ví dụ thể hiện quy ước rõ hơn văn xuôi

  • Đánh dấu mọi field required: đẩy model điền khi chưa đọc kỹ, dễ bịa; không giải quyết chất lượng phụ thuộc vị trí
