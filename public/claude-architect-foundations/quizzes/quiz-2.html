1. Claude Code: CLAUDE.md, rules, skills & permission

  • Scope theo vị trí file ≠ nội dung: CLAUDE.local.md chỉ cá nhân, không vào git → quy ước team đặt ở root CLAUDE.md Q3
  • .claude/settings.json: chứa permission, hook, env — không phải chỉ dẫn văn xuôi, không nạp làm context Q3
  • Path-scoped rule: *.test.tsx chỉ khớp root; dùng **/*.test.tsx để khớp mọi thư mục Q4
  • CLAUDE.md ≠ Skill: CLAUDE.md nạp mọi session; skill chỉ nạp name + description, body khi được gọi → rule "luôn/không bao giờ" vào CLAUDE.md Q13
  • Skill cá nhân: ~/.claude/skills/ + tên khác (gen-tests-local); trùng tên thì personal đè project Q10
  • allowed-tools trong SKILL.md: pre-approve tool chỉ trong lượt gọi skill; permissions.allow áp mọi session Q31
  • Plan mode: chỉ đọc, đề xuất; duyệt plan để thoát và implement trong cùng session, giữ hiểu biết Q28
  • @ file vs @ thư mục: file đưa nội dung vào prompt, thư mục chỉ ra danh sách tên file Q7
  • Glob vs Grep: Glob tìm theo tên/đường dẫn; Grep tìm theo nội dung → tìm caller dùng Grep rồi Read Q48, Q52

2. Prompt engineering: ví dụ, tiêu chí & định dạng

  • Đã có chỉ dẫn mà format vẫn lệch: thêm ví dụ mẫu đầy đủ (bảng, văn xuôi, checklist) trong thẻ <example> Q1
  • Mô tả bằng lời thất bại 2 lần: đưa vài cặp input → output mong đợi cho edge case (null, rỗng, thiếu) Q5
  • Tránh test trùng: @ spec file hiện có + yêu cầu chỉ thêm kịch bản chưa phủ Q7
  • Ví dụ có lý do ≠ ví dụ chỉ có nhãn: nhãn dạy khớp bề mặt; rationale dạy ranh giới quyết định Q15
  • Cặp tương phản: ghép idiom chấp nhận được với lỗi trông giống, nêu vì sao chỉ một cái cần báo Q27
  • Lost-in-the-middle: tóm tắt key findings đầu input + heading rõ cho từng nguồn Q9
  • Chuẩn hóa giá trị: nêu format chuẩn + quy tắc chuyển từng biến thể (PROJ-482) Q22
  • Từ ngữ system prompt kéo tool: "search" chung chung khớp search_tickets → nêu hành vi cụ thể (Grep) Q30
  • "CRITICAL/MUST" ≠ chỉ dẫn tốt: viết thường, khớp tiêu chí trong tool description Q30, Q47, Q60

3. Review tự động, confidence & người duyệt

  • Self-rated confidence ≠ xác suất hiệu chuẩn: chỉ là text; model hay tự tin sai đúng ca khó Q11, Q21, Q25
  • Phân bổ người review: confidence theo field, hiệu chuẩn ngưỡng trên mẫu có nhãn, đẩy ca thấp/mâu thuẫn cho người Q2
  • Accuracy tổng: 97% chung có thể che lỗi 40% ở một phân đoạn → kiểm theo segment Q2
  • Hand-off: tiêu chí tường minh + few-shot fix/hand-off; giọng giận dữ không đo độ khó Q11
  • Ngưỡng "90% chắc chắn": không thao tác được → liệt kê rõ cái cần báo và cái bỏ qua Q21
  • Confidence dùng để route: báo mọi finding, lọc ở bước sau, hiệu chuẩn trên tập có nhãn Q25
  • Category nhiễu: tạm gỡ docs/naming để giữ niềm tin, làm lại tiêu chí rồi bật lại Q19
  • Review độc lập: instance riêng chỉ nhận diff + tiêu chí; truyền rõ path và diff Q17

4. Structured output & thiết kế schema

  • Schema bảo đảm hình dạng ≠ sự thật: string hợp lệ vẫn sai nghĩa; field required ép bịa Q20, Q22
  • Field có thể không tồn tại: để optional + nullable (["string", "null"]) để model trả null thật Q20
  • Enum thiếu nhãn: thêm "other" + field mô tả; nullable thì mất thông tin Q18
  • JSON trong text hay hỏng: tool strict: true với schema payload, đọc input của tool_use Q29
  • --json-schema: cho output máy đọc; báo cáo người đọc thì làm phẳng bảng/văn xuôi Q1, Q22
  • Strict không kiểm business rule: lệnh refund đúng schema vẫn có thể chưa xác minh danh tính Q45
  • Attribution: subagent trả record claim + nguồn + section; input bọc tag tách content/source Q58

5. Chọn tool, MCP & báo lỗi từ tool

  • tool_choice: any ≠ chọn đúng tool: chỉ ép phải gọi tool; chọn tool nào do description Q24, Q30
  • Tool description: tín hiệu chính; 3–4 câu: trả gì, khi nào dùng thay Grep, phạm vi Q24, Q34
  • Ranh giới tool: ghi "chỉ cho ticket, không cho source code" trong description Q30
  • Tái dùng MCP server sẵn có cho GitHub; tự viết chỉ cho hệ thống nội bộ riêng Q32
  • MCP resource: schema DB, index wiki là dữ liệu đọc → publish resource, bỏ vòng discovery Q44
  • Rỗng ≠ lỗi: không khớp → kết quả rỗng thành công; timeout → isError: true Q6, Q43
  • Lỗi tự sửa được: errorCategory: validation, isRetryable, nêu format ORD- Q51
  • Protocol error ≠ tool execution error: lỗi nghiệp vụ trả trong tool result isError, model đọc được Q57

6. Subagent & điều phối hub-and-spoke

  • Subagent non-fork không thừa kế gì: không system prompt, history, tool result của cha → đưa hết vào delegation prompt Q38, Q46
  • Chỉ final message quay về: yêu cầu báo cáo kèm file path, call chain, lỗi thật Q6, Q38, Q58
  • Cô lập context: Explore subagent tìm call site, design + implement ở main Q12
  • Lookup dài dòng: giao subagent, trả tóm tắt; main giữ complaint và case facts Q59
  • Spawn subagent là tool call: thêm Task/Agent vào allowedTools của coordinator Q35
  • Giới hạn tool: tools trong AgentDefinition là allowlist; disallowedTools nhận mcp__github__* Q39
  • Hub chọn spoke: coordinator quyết subagent nào cần, không gọi cả ba mọi request Q40
  • Phần chung: coordinator khám phá core một lần, đưa tóm tắt vào từng prompt, vẫn song song Q42
  • Vấn đề liên quan nhau gửi chung một message; vấn đề độc lập làm tuần tự, kiểm từng cái Q16
  • Interview pattern: thêm AskUserQuestion vào tools + prompt hỏi edge case; không dùng trong subagent Q33

8. Session, trạng thái & context dài

  • Session lưu hội thoại ≠ filesystem: resume trả lại tool result cũ, không đọc lại file Q37, Q49, Q56
  • Resume vs fresh: đổi ít file → resume + nói file nào đổi; đổi nhiều/backend đổi → session mới + tóm tắt Q37, Q49, Q56
  • Fork: copy transcript, không copy file → mỗi nhánh một working directory Q50
  • --resume vs --continue: --name rồi --resume <tên> mở đúng session; continue lấy session gần nhất Q54
  • Crash recovery: subagent ghi manifest trạng thái từng module ra file; coordinator đọc khi khởi động lại Q8
  • Scratchpad file: ghi finding ra file; session mới đọc scratchpad + git log trước khi khám phá Q14
  • Case-facts block: cam kết của khách giữ nguyên trong mọi prompt, không bị summarize Q55

13. Mẹo làm bài thi

  • Loại ngay "self-rated confidence": xuất hiện ở khoảng 15 câu, gần như luôn là đáp án sai trừ khi kèm hiệu chuẩn trên tập có nhãn.
  • Loại "IMPORTANT/MUST/viết hoa": nhấn mạnh không thay được ví dụ, tiêu chí hay cơ chế code.
  • Hỏi "thiếu thông tin ở đâu?": subagent, resume, retry đều thất bại khi dữ liệu không nằm trong context.
  • "Never" = code: yêu cầu tuyệt đối → hook, schema, permission; không phải prompt.
  • Retry chỉ cho lỗi tạm thời: lỗi do input, schema hay vị trí thì retry lặp lại y lỗi.
  • "Select two" thường là đầu vào + đầu ra: prompt vào + báo cáo ra Q38, Q58, ghi + đọc scratchpad Q14, báo đủ + hiệu chuẩn Q25.
  • Chọn mức tối thiểu đúng phạm vi: skill-scoped thay vì toàn project, path rule thay vì luôn nạp.
