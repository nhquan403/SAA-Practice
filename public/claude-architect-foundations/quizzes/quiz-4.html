1. Tool use: tool_choice & định dạng tool result

  • Chọn tool ≠ số call ≠ input hợp lệ: tool_choice quyết tool nào; disable_parallel_tool_use quyết số call; strict quyết input đúng schema Q1, Q51
  • tool_choice 3 mức: auto tự do; any phải gọi một tool bất kỳ; {"type":"tool","name"} ép đúng tool đó Q51, Q32
  • Ép thứ tự: force extraction tool ở request đầu, trả tool_result rồi mới cho enrichment → dấu hiệu đề "enrichment fail nếu chạy trước" Q51
  • disable_parallel_tool_use: nằm trong object tool_choice; với auto = tối đa 1, với any/tool = đúng 1 Q1, Q51
  • Parallel tool use mặc định bật: tool bị ép vẫn có thể gọi nhiều lần → "ba call, mỗi section một" Q1
  • Thứ tự tool_result: user message ngay sau assistant turn; mọi tool_result đứng trước text, giữ nguyên tool_use_id Q6
  • Call không chạy được: vẫn trả tool_result với is_error: true, chung message với các result khác Q32
  • Manual loop vs Tool Runner: cần bước riêng mỗi call (log trước khi chạy) thì giữ manual loop Q6

2. Subagent: cô lập context & handoff

  • Subagent không thừa kế gì: không history, tool result, system prompt của parent; kênh duy nhất là delegation prompt Q10, Q23, Q24, Q44
  • Viết prompt delegate như brief kỹ sư mới: nêu path, quyết định đã chốt → dấu hiệu đề "the modules we discussed" Q23, Q44
  • Chuyển dữ liệu giữa subagent: coordinator chèn findings vào prompt subagent kế tiếp; tránh file chung, agent teams Q10
  • Fork: copy hội thoại; chỉ đáng khi cần nhiều background, không khi history đầy raw output Q23
  • Metadata phải đi kèm: ngày xuất bản là field cấu trúc riêng với mỗi finding → "mâu thuẫn" hóa ra là thay đổi theo thời gian Q2, Q24
  • page_age: ngày site cập nhật, không phải ngày viết; lấy ngày từ nội dung Q24
  • Explore subagent: read-only, không nạp CLAUDE.md, 3 mức thoroughness, vẫn tính usage limit Q25
  • Explore không resume được: việc nối nhiều lượt dùng general-purpose/custom subagent (có agentId) Q28
  • Không delegate việc đơn giản: tìm call site bằng Grep trực tiếp; Glob chỉ match path Q8

3. Điều phối multi-agent, workflow & xử lý lỗi

  • Recovery cục bộ trước: lỗi tạm thời retry backoff trong subagent; lỗi không giải được mới báo coordinator kèm context Q14
  • Báo lỗi có cấu trúc: loại lỗi, query đã thử, kết quả dở; không "search unavailable" chung chung Q14, Q18
  • Không nuốt lỗi: kết quả dở ≠ thành công; lỗi truy cập ≠ kết quả rỗng hợp lệ Q14, Q18
  • Coordinator là hub: mọi lỗi về coordinator để retry, đổi hướng hoặc dùng partial findings Q10
  • Vòng lặp refinement: cần cả nhánh thất bại — cap retry mỗi gap, rồi annotate coverage Q7
  • Bước cố định ≠ agent: bước biết trước → prompt chaining/pipeline trong code; agent thêm chi phí và biến động Q33, Q45
  • Chaining tách API call: lưu output mỗi stage, rẽ nhánh bằng code (không chạy stage 2 khi scan rỗng) Q45
  • Batch song song: chỉ việc độc lập chung một response; việc phụ thuộc delegate ở lượt sau Q32, Q33
  • Mơ hồ chỉ người dùng giải được: liệt kê ứng viên + ID ổn định, hỏi người chọn Q13, Q29

4. Thiết kế tool & MCP

  • Tool availability là kiểm soát kiến trúc: field tools trong AgentDefinition giới hạn tool; ≠ allowedTools (chỉ auto-approve) Q11, Q15
  • Description: tín hiệu chọn tool chính; nói rõ khi nào KHÔNG dùng Q15
  • Description bị cắt 4.096 ký tự: đặt mục đích, dữ liệu trả, so sánh Grep lên đầu Q42
  • MCP resource: dữ liệu đọc (catalog) host fetch và gắn làm context trước mọi tool call Q34
  • Error content của tool: lý do dễ hiểu + bước tiếp được duyệt; sửa ở tool lợi cho mọi agent Q39
  • isError vs retriable: isError chuẩn MCP; retriable là quy ước riêng của team Q39
  • Handoff bắt buộc đủ: input schema có required fields (files, root cause, fixes, đề xuất) Q40
  • Build vs reuse: hệ thống phổ biến (Jira) dùng connector có sẵn; hệ thống nội bộ mới tự viết MCP server Q43
  • Biến credential bảo vệ: ANTHROPIC_AUTH_TOKEN trong url/headers server từ xa thành rỗng → đổi tên biến khác Q41

6. Claude Code: session, context & workflow

  • --continue ≠ --resume: continue = session gần nhất trong thư mục; resume = session cụ thể theo ID, tên hoặc picker Q5, Q37, Q38
  • Persistence là tiền đề resume: --no-session-persistence không lưu gì; cần bỏ flag + --name Q3
  • Đặt/đổi tên: --name gắn tên session mới; /rename đổi tên session hiện tại; /resume chuyển trong session Q37, Q38
  • Script headless: lưu session_id từ --output-format json, resume bằng ID, nêu file đã đổi cần đọc lại Q5
  • /compact vs /clear vs /rewind: compact giữ quyết định; clear cho việc không liên quan; rewind bỏ hướng sai Q9
  • Compaction mất chi tiết: mapping file–dòng, constraint cụ thể → ghi scratchpad file, đọc lại từ mọi session Q19, Q30
  • Sau compaction: tự đọc lại tối đa 5 file gần đây; file > 5.000 token chỉ còn path Q30
  • Edit tool: match literal, unique; nhiều chỗ → replace_all; no-match → Read rồi copy nguyên văn Q12
  • Để Claude tự kiểm: viết test trước, Claude chạy và sửa đến khi pass Q17
  • Thay đổi nhỏ, rõ: sửa trực tiếp, nêu file + rule + check; plan mode chỉ khi mơ hồ, nhiều file Q26
  • CI --json-schema: chấp nhận khi subtype success VÀ có structured_output Q20

13. Mẹo làm bài thi

  • Đề đòi "guarantee": loại phương án prompt/few-shot; chọn cấu hình API, schema, code, permission.
  • Đọc chữ "already": đề nói rule viết/description đã thử thì loại phương án lặp lại nó Q11, Q15, Q47, Q53.
  • Mỗi cơ chế một chiều: chọn tool, số call, shape input, nội dung — đừng gán nhầm.
  • Subagent = tờ giấy trắng: phương án "subagent thừa kế system prompt/history" luôn sai.
  • Phương án đúng nhưng sai hoàn cảnh: nhiều đáp án sai là kỹ thuật thật; tìm ràng buộc trong đề loại nó.
  • "Select two": thường hai lớp bổ trợ — dữ liệu/lỗi Q10, availability/description Q15, thứ tự/format Q32, cờ trong schema/kiểm trong code Q49.
  • Ưu tiên đo offline: có dữ liệu lịch sử thì eval trước khi bật lại cho người dùng.

Học đáp án đúng chỉ giải được đúng câu đó. Hiểu vì sao từng đáp án sai lại sai giúp nhận diện được cả họ câu hỏi tương tự, kể cả khi đề đổi cách hỏi. Mỗi dòng dưới đây là một câu, liệt kê các đáp án sai và lý do sai thật sự — đúc kết từ chính phần giải thích của đề, không phải suy đoán.

  • Giữ giá trị nguồn mới hơn, bỏ giá trị kia: mất xu hướng tăng trưởng; và không có ngày thì cũng không biết nguồn nào mới hơn
