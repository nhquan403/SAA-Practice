1. Claude Agent SDK: permission mode, session & input mode

  • Plan mode: chỉ đọc + đề xuất, mọi lệnh sửa file phải qua canUseTool → dấu hiệu đề "duyệt cách làm trước khi sửa file" Q1
  • Đổi mode giữa session: setPermissionMode / set_permission_mode, áp dụng ngay, giữ context → dấu hiệu đề "duyệt plan xong thì sửa tự động" Q1
  • dontAsk ≠ bypassPermissions: dontAsk từ chối mọi thứ cần hỏi; bypass chạy hết không hỏi; acceptEdits tự duyệt sửa file Q1, Q43
  • Fork session: fork_session tạo session ID mới có bản sao lịch sử, gốc giữ nguyên; không rẽ nhánh file → dấu hiệu đề "thử giả thuyết khác" Q3
  • Resume: chỉ nối tiếp cùng session, kể cả hai query song song; không tạo nhánh độc lập Q3
  • Streaming input ≠ single message: streaming (khuyên dùng) cho đính ảnh, xếp hàng message, interrupt; single chỉ one-shot/lambda Q4

2. Workflow pattern & kiến trúc multi-agent

  • Evaluator-optimizer: sinh → đánh giá → feedback, lặp có retry limit → dấu hiệu đề "có tiêu chí rõ, sửa tới khi đạt" Q5
  • Parallelization voting: chạy cùng việc bằng nhiều prompt, gắn cờ theo ngưỡng phiếu → dấu hiệu đề "review bảo mật hay bỏ sót" Q6
  • Chaining / routing: chuỗi cố định một lượt / gửi tới một handler; không tự sửa, không đa góc nhìn Q5, Q6
  • Tự review cùng conversation ≠ call review riêng: cùng conversation lặp điểm mù; call riêng + policy + checklist mới bắt lỗi Q41, Q6
  • Coordinator giữ cửa: giao mục tiêu, format, ranh giới; giới hạn tool/token; validate handoff trước khi phát hành, không audit sau Q2
  • Agent nhiều context window: từng feature một, git commit rõ, file tiến độ cho session sau đọc đầu tiên Q38

3. Tool use: agentic loop, định nghĩa tool & độ an toàn

  • Agentic loop: lặp khi stop_reason == "tool_use", append assistant turn + tool_result, có giới hạn vòng → dấu hiệu đề "dừng giữa chừng" Q7
  • max_tokens cắt tool_use: kiểm stop_reason trước, không chạy tool dở; retry với max_tokens lớn hơn Q48
  • Parallel tool use: bật mặc định; tắt bằng disable_parallel_tool_use trong tool_choice → dấu hiệu đề "tool phụ thuộc kết quả tool kia" Q12
  • Mô tả tool: yếu tố quan trọng nhất, ≥ 3–4 câu: làm gì, khi nào dùng/không dùng, caveat Q49
  • Programmatic tool calling: allowed_callers = code execution, lọc kết quả trong code → dấu hiệu đề "hàng trăm kết quả, cần vài cái" Q53
  • Citation RAG: tool trả block search_result (source, title, content); citation tắt mặc định, phải bật Q17
  • Idempotency key ≠ idempotentHint: key lưu bền vững chặn charge trùng; hint chỉ là metadata Q15

4. Server tools & MCP

  • Web fetch: chỉ fetch URL đã có trong user message/tool result; URL ở system prompt bị url_not_allowed Q9
  • Code execution: container không internet, không cấu hình mở được; file qua container_upload, dùng thư viện sẵn → dấu hiệu đề "pip install fail" Q45
  • MCP connector: mcp_servers URL HTTPS, mcp_toolset làm allowlist; chỉ tool call, không stdio Q20
  • stdio ≠ Streamable HTTP: stdio là process cục bộ; Streamable HTTP cho nhiều client, load balancer, validate Origin + OAuth Q50
  • Credential MCP: token ngắn hạn theo user, audience là server; cấm token passthrough (confused deputy) Q47
  • Form mode ≠ URL mode elicitation: form cho input thường; API key/mật khẩu bắt buộc URL mode, không qua model Q51
  • ZDR: MCP connector và Files API đều không đủ điều kiện ZDR Q19

5. Cấu hình Claude Code

  • disable-model-invocation: true ≠ user-invocable: false: cái đầu chỉ người gọi (deploy); cái sau chỉ Claude gọi Q22
  • context: fork: skill chạy trong subagent, không thấy lịch sử, giữ context chính sạch → dấu hiệu đề "đọc hàng trăm file" Q22
  • /rewind: khôi phục code + hội thoại; file do Bash sửa phải dùng git; /clear không hoàn tác file Q25
  • PreToolUse ≠ PostToolUse: Pre chặn được (exit 2 / permissionDecision: "deny"); Post chỉ phản hồi, không hoàn tác Q46
  • Sandbox Bash: proxy allowlist domain (mặc định trống) + sandbox credentials deny; CLAUDE.md không phải ranh giới Q43
  • GitHub Actions: /install-github-app hoặc claude-code-action, key ở GitHub Secrets → dấu hiệu đề "@claude trong PR" Q24
  • Plugin + marketplace: đóng gói skill/hook/MCP, có version, auto-update → dấu hiệu đề "nhiều team, một lệnh cài" Q52

6. Prompt caching & extended thinking

  • Pre-warm cache: max_tokens: 0 + breakpoint tường minh trên block chung; automatic caching sẽ trượt → dấu hiệu đề "request đầu chậm" Q10
  • Thứ bậc tools → system → messages: đổi tool_choice mất cache messages; đổi/xếp lại tool mất toàn bộ Q36
  • Thinking blocks: gửi lại nguyên vẹn thinking + redacted_thinking cùng tool_use, không sửa/lọc Q11
  • budget_tokens: ≥ 1.024 và < max_tokens; thinking tính phí như output, ước tính theo usage thực Q30
  • Claude Opus 5.5: chỉ adaptive thinking; đổi temperature/top_p/top_k hoặc forced tool use → 400; dùng auto + strict tool Q33

7. Vận hành API & SDK: batch, lỗi, retry, streaming

  • Message Batches: giá 50%, tối đa 24 giờ, khớp bằng custom_id, gửi lại expired → dấu hiệu đề "chi phí là chính, chờ được" Q13
  • 529 overloaded: SDK retry 2 lần; trang tương tác dùng circuit breaker + giảm max_retries + fallback Q14
  • 400 spend limit ≠ 401 key: "workspace API usage limits" là 400, sửa ở Billing; key thu hồi là 401 Q26
  • Phân loại lỗi: 429/529 tạm thời tự retry; 400 retry vô ích; page theo tác động user, vẫn log phần còn lại Q27
  • Backpressure: asyncio.Queue(maxsize), đóng stream khi browser ngắt; stream=True ít bộ nhớ hơn helper Q16
  • Pagination: lặp for để auto-paginate; limit chỉ là cỡ trang → dấu hiệu đề "luôn đúng 20 mục" Q31
  • extra_body: truyền tham số SDK cũ chưa có, giữ retry/timeout → dấu hiệu đề "unexpected keyword argument" Q32

8. Chọn model, vision, embeddings & lưu trữ dữ liệu

  • Models API: đọc max_input_tokens, capabilities lúc runtime thay bảng hardcode Q23
  • Efficiency-first: việc đơn giản, khối lượng lớn → thử Haiku trên bộ mẫu có nhãn trước, chưa đạt mới nâng Q28
  • Effort ≠ đổi model: effort chỉnh tốc độ/chi phí trong cùng model, thường là đòn bẩy tốt hơn Q34
  • Không deterministic: lệch ~2% nhãn là bình thường kể cả temperature thấp; đo trên eval, thêm ví dụ ca biên Q29
  • Nhiều ảnh: gắn nhãn Image 1/2; ảnh lớn bị downscale → crop vùng cần đọc Q8
  • Không có embeddings endpoint: dùng Voyage AI tạo vector; token counting chỉ đếm số token Q21
  • ZDR theo tính năng: Messages + prompt caching đủ điều kiện; Files API không → gửi PDF inline base64 Q19

9. Prompt engineering, đánh giá & guardrail

  • Few-shot ca khó: thêm cặp input bất thường + output đã duyệt bên cạnh ví dụ thường, chạy lại eval Q39
  • Quy tắc mâu thuẫn: thay bằng chỉ dẫn có điều kiện kèm lý do; không viết hoa, lặp lại Q40
  • Không có structured outputs: schema JSON tường minh trong system, nói điều cần làm, app vẫn validate Q42
  • Yêu cầu kiểm thử được: "chính xác" → bộ có nhãn + ngưỡng; "nhanh" → p95 ở tải đỉnh Q18
  • Nâng cấp model: eval riêng chấm chọn tool + argument trên cả hai model, rồi rollout dần Q35
  • "Vừa context" ≠ "đạt yêu cầu": chưa có ưu tiên thì định nghĩa tiêu chí chấp nhận trước, rồi mới chọn chiến lược Q37
  • Chính sách văn bản tường minh: keyword/regex chặn trước khi xuất bản, không dựa Claude tuân thủ Q44

13. Mẹo làm bài thi

  • Enforce thắng lời dặn: "bảo đảm", "chặn trước" → code, hook, sandbox, không phải prompt Q15, Q43, Q44, Q46

  • Giữ context: đổi mode, fork, file tiến độ thay vì tóm tắt sang session mới Q1, Q3, Q38

  • Đo trước, đổi kiến trúc sau: thử effort, đo nhất quán, eval riêng trước Q29, Q34, Q35
  • Bám thứ tự ưu tiên của đề: chờ được → batch; một giây → không batch Q13, Q14, Q28, Q37
