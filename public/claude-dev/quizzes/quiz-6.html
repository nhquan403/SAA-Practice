1. Kiến trúc agent, Agent SDK & subagent

  • Workflow + agent lai: workflow cho bước thường lệ, agent chỉ ở điểm cần quyết định → dấu hiệu đề "flexibility only at that point" Q8
  • State graph: nhiều giai đoạn, duyệt người, tạm dừng nhiều ngày → checkpoint + interrupt, Claude chỉ trong node phán đoán → dấu hiệu đề "pause for days, resume" Q4
  • Subagent song song: việc điều tra độc lập, đọc nhiều file; context riêng, trả tóm tắt → dấu hiệu đề "keep main conversation clean" Q5
  • Subagent read-only: giới hạn tools còn Read, Grep, Glob — cấu hình, không phải lời dặn → dấu hiệu đề "must only read" Q6
  • Claude Agent SDK: agent loop có sẵn tool file/lệnh; query + allowed tools + permission mode, lưu session ID để resume → dấu hiệu đề "scheduled, resume" Q7
  • SIGTERM → exit 143: turn bỏ dở; dừng gọn bằng SIGINT hoặc interrupt() trước; SIGKILL tệ hơn → dấu hiệu đề "exit code 143" Q16
  • Bước biết trước ≠ quyết định theo ngữ cảnh: biết trước → workflow/state graph; ngữ cảnh → agent. "Agent tự do toàn bộ" là sai Q4, Q8

2. Context engineering, memory & compaction

  • Just-in-time context: giữ tham chiếu nhẹ (path, query), tải qua tool khi cần → dấu hiệu đề "preload everything, new files missed" Q1
  • Memory nhiều session: initializer session tạo progress log + checklist; đánh dấu xong chỉ sau test end-to-end → dấu hiệu đề "marked done but fail" Q2
  • Compaction: luật trong prompt đầu có thể mất; luật lâu dài đặt trong CLAUDE.md qua settingSources → dấu hiệu đề "compact_boundary" Q3
  • Context editing: clear_tool_uses_20250919 xóa tool result cũ; đặt clear_at_least cho đáng mất cache → dấu hiệu đề "rarely needs tool result again" Q9
  • Temperature: chỉ là độ ngẫu nhiên, không mở rộng context; input dài → chunk/tóm tắt + token counting → dấu hiệu đề "transcript too long" Q38
  • Format drift: end_turn nhưng JSON hỏng sau vài lượt → do context loãng; nhắc format cuối, cắt lịch sử, structured outputs, validate Q44
  • Prompt caching ≠ tiết kiệm context: cache giảm chi phí/độ trễ, token cache vẫn chiếm context window Q1, Q9, Q38
  • CLAUDE.md ≠ viết hoa/lặp trong prompt: chỉ CLAUDE.md sống sót qua compaction Q3

3. Structured outputs & tool use

  • Schema giới hạn: minimum, minLength/maxLength, additionalProperties: true → lỗi 400; format: "email" được; kiểm tra trong code → dấu hiệu đề "400 before generation" Q10
  • Thứ tự property: required luôn đứng trước optional → map CSV theo tên hoặc đặt mọi field required → dấu hiệu đề "wrong column" Q40
  • Pydantic + messages.parse: thay regex, nhận object có kiểu; luật nghiệp vụ vẫn kiểm sau parse → dấu hiệu đề "regex parsing prose" Q41
  • Grammar cache: compile lần đầu, cache 24h từ lần dùng cuối; đổi cấu trúc mới mất cache, đổi tên/description thì không → dấu hiệu đề "new schema per request" Q42
  • Strict tool use: chỉ bảo đảm tham số đúng schema; quyền sở hữu kiểm trong code, trả is_error (BOLA) → dấu hiệu đề "strict mode makes it safe" Q51
  • Schema đúng ≠ dữ liệu đúng ≠ được phép: schema lo hình dạng; giới hạn, nghiệp vụ, quyền kiểm trong code Q10, Q41, Q51

4. Cấu hình Claude Code: settings, MCP & plugin

  • Phạm vi settings: .claude/settings.json commit cho team; settings.local.json cá nhân, git-excluded; ~/.claude mọi dự án một máy → dấu hiệu đề "personal override" Q27
  • Server-managed settings: MDM không tới cloud session; thêm server-managed ở admin console, giữ MDM cho laptop; kiểm bằng /status → dấu hiệu đề "cloud sessions" Q18
  • .mcp.json biến môi trường: ${VAR}, ${VAR:-default} trong url/headers, commit không lộ token → dấu hiệu đề "secret scanner blocked" Q19
  • Tool search: tự tắt khi ANTHROPIC_BASE_URL không first-party; gateway hỗ trợ thì ENABLE_TOOL_SEARCH=true → dấu hiệu đề "tool definitions fill context" Q11
  • Plugin auto-update: tắt mặc định cho marketplace bên thứ ba; bật trong /plugin hoặc claude plugin update → dấu hiệu đề "plugin not updating" Q12
  • Endpoint-managed (MDM) ≠ server-managed: MDM chỉ phủ máy dev; server-managed phủ cloud session — cần cả hai Q18

5. Mở rộng Claude Code: hooks, skills & output style

  • PreToolUse hook: chạy trước permission mode, deny chặn cả bypassPermissions; kèm lý do rõ; PostToolUse quá muộn → dấu hiệu đề "even in broad permission mode" Q46
  • Prompt hook: type: "prompt" trên Stop để model đánh giá "xong chưa"; SessionStart không hỗ trợ → dấu hiệu đề "completion depends on conversation" Q50
  • Output style: định hình mọi phản hồi, mỗi người tự chọn; CLAUDE.md vẫn nạp cho kiến thức dự án → dấu hiệu đề "every response explains" Q49
  • Skill: nạp theo nhu cầu, đầu session chỉ thấy description; quy trình thỉnh thoảng → .claude/skills → dấu hiệu đề "only for specific tasks" Q52
  • Skill vs MCP: skill đóng gói chỉ dẫn/script; MCP kết nối hệ thống sống; bổ trợ nhau → dấu hiệu đề "live data, external systems" Q53
  • Hướng dẫn ≠ cưỡng chế: CLAUDE.md/prompt là lời dặn; chặn chắc chắn phải là PreToolUse hook trả deny Q46
  • Chọn cơ chế: mọi phản hồi → output style; kiến thức dự án → CLAUDE.md; thỉnh thoảng → skill; dữ liệu sống → MCP Q49, Q52, Q53

6. Model, tham số API & chi phí

  • Effort: trong output_config; Opus 5.5, Haiku 5.5 mặc định medium, model khác high → dấu hiệu đề "shorter answers after moving to Opus 5.5" Q31
  • Adaptive thinking: Claude 4.7+ type: "enabled" lỗi 400; dùng "adaptive", bỏ budget_tokens, chỉnh bằng effort → dấu hiệu đề "budget_tokens, 400" Q32
  • Fast mode: cùng model, output nhanh tới 2.5x (OTPS, không TTFT), giá cao hơn, đổi mode mất cache, không dùng Batch → dấu hiệu đề "edits slow to appear" Q30
  • Long context pricing: chỉ Haiku 5.5 tính giá cao khi prompt >100k token, tính cả cache, theo từng request → dấu hiệu đề "Haiku, higher price" Q36
  • Chọn model: đánh giá chất lượng, độ trễ, chi phí cùng lúc trên workload thật, không theo benchmark → dấu hiệu đề "all three constrained" Q37
  • Rate limit: đọc header anthropic-ratelimit-* để giãn nhịp, tôn trọng retry-after khi 429 → dấu hiệu đề "raw HTTP, slow down" Q23
  • Kiểm chứng chi phí: Usage and Cost API, nhóm theo workspace/model, tách loại token, so dự báo trước khi đổi gì → dấu hiệu đề "before anyone changes settings" Q35
  • SDK Python: bản minor có thể phá tương thích; pin trong lockfile, nâng qua PR có type check + test → dấu hiệu đề "minor upgrade broke" Q34
  • max_tokens ≠ độ sâu/context: chỉ giới hạn độ dài phản hồi; chỉ liên quan khi stop_reason là max_tokens Q23, Q31, Q44

7. Files API & Message Batches

  • File thuộc workspace: mọi key trong workspace đọc được; không nhận file_id từ client, workspace riêng mỗi khách → dấu hiệu đề "user supplies file_id" Q13
  • Vòng đời file: tồn tại tới DELETE hoặc expires_at; metadata giữ 30 ngày; ngừng app → xóa file + revoke key → dấu hiệu đề "decommission" Q20
  • Tải file: chỉ file do skills/code execution tạo; file đã upload trả 400 → tự lưu bản gốc → dấu hiệu đề "download uploaded file" Q22
  • Kết quả batch: succeeded/errored/canceled/expired; chỉ retry expired và lỗi server; thứ tự không bảo đảm → join custom_id Q24
  • Lưu kết quả batch: tải được 29 ngày từ lúc tạo; 24h là thời gian xử lý → lưu ngay → dấu hiệu đề "results gone after weeks" Q33
  • Expiration ≠ kiểm soát truy cập: cách ly = workspace + kiểm sở hữu; dọn dẹp = xóa chủ động + revoke key Q13, Q20

8. Yêu cầu, đánh giá & quản lý thay đổi

  • Chức năng ≠ hiệu năng: chức năng là làm gì; hạ tầng là tải/tốc độ (300 cuộc đồng thời, 800 ms) → dấu hiệu đề "concurrent calls" Q14
  • Tiêu chí thành công: cụ thể, đo được; đổi "chính xác, nhanh" thành ngưỡng số trên held-out (p95) → dấu hiệu đề "vague accurate, fast" Q15
  • Handler dùng chung: unit test mỗi loại block kể cả loại chưa biết + integration test luồng đầy đủ → dấu hiệu đề "new content block type" Q21
  • Tham số deprecate: viết regression check trước, migrate từng nhóm và validate; compile được không đủ → dấu hiệu đề "edge case differs" Q25
  • Đổi prompt: nghĩa field có thể đổi dù tên giữ nguyên; kiểm hợp đồng downstream, regression ~100% → dấu hiệu đề "downstream consumers" Q26
  • So phương án prompt: gom ca lỗi đại diện có đáp án vào eval, so mọi phương án trên cùng bộ → dấu hiệu đề "nobody can prove" Q39
  • Bằng chứng ≠ demo: test lặp lại, eval đại diện trước khi ship; screenshot, 5 mẫu, model tự chấm đều không tính Q15, Q21, Q39

9. Vận hành, truy vết & bảo mật

  • Request ID: header request-id, SDK _request_id; log kèm model, phiên bản prompt, không log key → dấu hiệu đề "support case" Q17
  • Lỗi giữa stream: HTTP 200 rồi error event; lấy request ID từ response, ghi loại event → dấu hiệu đề "overloaded mid-stream" Q28
  • Điều tra refusal: mở trace đầy đủ (system prompt, retrieve, stop_details), so với trace thành công → dấu hiệu đề "stop_reason refusal" Q29
  • Hallucination: kiểm claim với nguồn tin cậy, giới hạn vào tài liệu, citations; confidence tự gán không tính → dấu hiệu đề "downstream treats as fact" Q43
  • Key bị lộ: revoke ngay trong Console, tạo key mới, secrets manager; xóa git history chưa đủ → dấu hiệu đề "public repo, unusual usage" Q45
  • Threat model LLM: prompt injection trực tiếp/gián tiếp, jailbreak, rò rỉ context; OWASP xếp injection đầu → dấu hiệu đề "partner documents" Q47
  • Least privilege Console: contractor là Workspace Developer chỉ ở sandbox; org admin tự là admin mọi workspace → dấu hiệu đề "contractor" Q48
  • Request ID ≠ timestamp/hash: chỉ request ID giúp support tìm đúng request Q17, Q28
  • Cấu hình/code ≠ lời dặn: ranh giới bảo mật là role, workspace, kiểm sở hữu, revoke key Q45, Q48, Q51

13. Mẹo làm bài thi

  • "enforce", "even if", "must never": loại lời dặn prompt; chọn cấu hình/code Q6, Q46, Q51
  • "diagnose first": chọn thu thập bằng chứng (trace, usage) trước khi đổi gì Q29, Q35, Q44
  • "Tăng max_tokens": mồi nhử, trừ khi stop_reason là max_tokens Q31, Q44
  • "Select two": hai nửa bổ trợ — file_id server + workspace Q13, xóa + revoke Q20, hook + lý do Q46, style + CLAUDE.md Q49
  • Model tự đánh giá: tự chấm, tự gán confidence, sinh trùng — không phải bằng chứng Q15, Q43, Q44
  • Tên model cụ thể: có chi tiết riêng — effort mặc định, long context, adaptive thinking Q31, Q32, Q36
  • "minimal custom code": chọn tính năng sẵn có (context editing, prompt hook, Agent SDK) Q7, Q9, Q50
  • Bằng chứng trước, kết luận sau: loại đáp án tóm tắt trước review hay release trước kiểm Q5, Q39

14. Bẫy thường gặp

  • Token cache vẫn chiếm context: caching chỉ giảm chi phí, độ trễ Q1, Q9, Q38
  • Strict tool use ≠ phân quyền: đúng schema không có nghĩa được phép Q51
  • File thuộc workspace: xoay key hay hết hạn không chặn dùng file_id người khác Q13, Q20
  • MDM không tới cloud session Q18
  • Fast mode: không phải model nhỏ, không rẻ hơn; đổi mode mất cache Q30
  • Adaptive thinking: không setting nào giống hệt budget cố định cũ Q32
  • /reload-plugins: không tải bản mới từ marketplace Q12

  • SIGKILL / exit 143: đều sai; dùng SIGINT hoặc interrupt() Q16
  • Org admin: tự là Workspace Admin mọi nơi — không cấp cho contractor Q48

Học đáp án đúng chỉ giải được đúng câu đó. Hiểu vì sao từng đáp án sai lại sai giúp nhận diện được cả họ câu hỏi tương tự, kể cả khi đề đổi cách hỏi. Mỗi dòng dưới đây là một câu, liệt kê các đáp án sai và lý do sai thật sự — đúc kết từ chính phần giải thích của đề, không phải suy đoán.

CâuĐáp án sai & vì sao sai
Q1
  • Nạp sẵn nhiều kết quả search hơn: càng lãng phí và chậm, vẫn chỉ có những gì search trả về trước khi task bắt đầu, làm loãng sự chú ý của model
  • Tóm tắt mỗi tài liệu, không mở được bản gốc: mất chi tiết agent cần ở bước sau và vẫn bỏ sót file thêm trong lúc làm
  • Đưa hết vào system prompt có prompt caching: cache chỉ giảm giá, tài liệu vẫn chiếm context mỗi request và bộ tài liệu bị đóng băng từ đầu
Q2
  • Lưu nguyên transcript mỗi session vào /memories: nạp quá nhiều context và giữ luôn các lần đánh dấu "xong" chưa kiểm chứng
  • Tăng max_tokens, đổi model context lớn hơn: backlog 40 tính năng vẫn kéo dài nhiều session, và không có gì kiểm chứng tính năng trước khi đánh dấu xong
  • Để Claude ghi memory tùy hứng, bố cục tự do: chính là cách ad hoc mà pattern multisession thay thế, mỗi session lại phải đi tìm trạng thái
Q3
  • Lặp lại luật, viết hoa CRITICAL trong prompt đầu: compaction vẫn thay các message đầu bằng bản tóm tắt, luật còn hay mất vẫn phụ thuộc summarizer
  • Tắt auto compaction: đổi việc quên luật lấy việc run hỏng vì vượt context window
  • PreCompact hook lưu transcript ra storage: hữu ích cho audit nhưng agent không đọc archive đó, luật vẫn biến mất khỏi context đang làm việc
Q4
  • Một hội thoại dài, nhờ Claude tự theo dõi trạng thái: nguồn sự thật thành văn bản do model sinh, không ép được luật chuyển, không resume từ checkpoint được
  • Agent tự trị tự chọn bước chuyển, ghi log tool: luật chuyển đã cố định nên để model chọn tạo biến thiên không được phép; log không phải checkpoint
  • Vòng lặp stateless, dựng lại trạng thái từ log: không lưu tiến độ bền vững, dựng lại từ log chậm và dễ sai khi tạm dừng nhiều ngày
Q5
  • Chạy tuần tự trong hội thoại chính, compact giữa các lượt: mọi file vẫn vào context chính, compaction có thể mất chi tiết, lại chậm hơn
  • Xen kẽ ba góc nhìn trong một phản hồi dài: trộn bằng chứng, mất chiều sâu từng mảng, context chính vẫn đầy
  • Viết tóm tắt rủi ro trước từ tên thư mục: kết luận trước bằng chứng, gây confirmation bias
Q6
  • Dặn trong prompt chỉ báo cáo, không sửa: chỉ dẫn hướng hành vi nhưng không lấy đi khả năng, mong muốn sửa lỗi của Claude có thể lấn át
  • Chạy review trong context của agent chính: mất cô lập context, và agent chính cần quyền sửa nên cũng không read-only
  • Cho đủ tool, script đêm revert file bị sửa: lỗi đã xảy ra trước khi revert, bản release build trong khoảng đó đã dính thay đổi
Q7
  • Client SDK + tự viết loop, tool, session, permission: đúng phần việc team muốn tránh, Agent SDK đã có sẵn
  • Chạy CLI tương tác, có người duyệt từng lệnh: phá mục đích job tự động, giữ terminal mở giữa các lần chạy rất mong manh
  • Gửi đường dẫn repo vào Messages API một lần: Messages API chỉ sinh phản hồi, không đọc file hay chạy lệnh được
Q8
  • Manager + subagent cho từng bước kiểm tra, thêm specialist cho mỗi bố cục: thêm điều phối không cần thiết, phình theo từng bố cục mới
  • Gọi agent trước mỗi bước kiểm tra đã định: thêm độ trễ và hành vi không nhất quán cho đường đi đã biết
  • Agent tự trị hoàn toàn cho mỗi biểu mẫu: thêm tùy ý vào thứ tự đã cố định, khó dự đoán, khó test và audit
Q9
  • Nhờ Claude tóm tắt mỗi tool result một dòng, vẫn giữ bản gốc: bản gốc vẫn trong request nên input không nhỏ đi, lại tốn thêm output token
  • Chuyển tool result vào system prompt: nội dung cache vẫn tính vào context window, và nội dung thay đổi làm mất cache mỗi request
  • Hạ max_tokens để dành chỗ cho input: dễ cắt cụt phản hồi, các tool result cũ vẫn nằm đó nên vẫn sớm chạm giới hạn
Q10
  • Viết lại bằng regex có {n,m} lớn và lookahead: regex của structured outputs không hỗ trợ lookahead/lookbehind và quantifier phạm vi lớn, vẫn lỗi 400
  • Đặt additionalProperties thành true: structured outputs bắt buộc false cho object, true cũng gây lỗi; không có chế độ "gợi ý"
  • Bỏ structured outputs, nhờ prompt trả JSON: mất bảo đảm khớp schema, phải tự xử lý output hỏng

  • Cả bốn đều là yêu cầu chức năng: có trong ghi chú không làm nó thành chức năng; concurrency và latency sẽ không có người phụ trách
  • Chuyển máy cho nhân viên là yêu cầu hạ tầng: đó là hành vi assistant phải làm, telephony chỉ là chi tiết triển khai

  • Luật sư duyệt demo 5 hợp đồng do kỹ sư chọn: mẫu không đại diện, không held-out, chủ quan, quá ít để ước lượng 95%

  • Nới khung thời gian vì không có cách dừng turn từ bên ngoài: có cách — SIGINT hoặc interrupt(); nới thời gian chỉ trì hoãn vấn đề

  • Thay 10 ví dụ bằng một ca khó nhất: mất độ phủ, ví dụ nên liên quan và đa dạng, không so được các phương án
  • Giữ prompt, gửi lại tới khi ra đúng: phải biết trước đáp án, tốn nhiều lần gọi, lỗi vẫn còn nguyên
Q40
  • Dời notes xuống cuối schema: required luôn đứng trước optional, nên thứ tự vẫn không như writer mong đợi
  • Dặn Claude xuất đúng thứ tự schema: thứ tự do schema và danh sách required quyết định, không do model

Q41
  • Giữ văn xuôi, thêm regex cho mỗi kiểu heading: mỗi biến thể mới lại cần pattern mới, sự mong manh đến từ việc parse văn xuôi
  • Nhờ Claude trả bảng markdown: vẫn là văn bản tự do, thứ tự cột, chính tả, format có thể đổi
  • Nhận mọi JSON hợp lệ, downstream tự suy luận: JSON không schema vẫn thiếu field, sai kiểu; chuyển việc parse mong manh sang chỗ khác
Q42
  • Structured outputs cộng độ trễ cố định cho mọi request: chỉ lần đầu dùng một schema mới tốn thêm, sau đó grammar được cache
  • Tên khách trong description làm mất grammar cache: đổi name hay description không làm mất cache, đổi cấu trúc mới làm mất
  • Schema dài vượt kích thước cache, chia nhỏ request: tài liệu không nói về giới hạn kích thước cache; chia nhỏ nhân số lần gọi và vẫn compile
Q43
  • Nhờ Claude gán % confidence, nhận claim trên ngưỡng: con số do model sinh cũng cần kiểm chứng, không chắc đã calibrate
  • Duyệt tay từng mô tả trước khi dùng: không mở rộng được cho hàng nghìn mô tả; người duyệt chỉ nên dành cho ca khó
  • Sinh nhiều lần, coi sự trùng khớp là bằng chứng: các lần sinh có thể cùng sai, nhất quán không phải xác nhận độc lập
Q44

  • Nhờ Claude tự khẳng định đúng schema: tự đánh giá không phải kiểm tra dữ liệu, Claude có thể tự tin duyệt output sai
  • Chỉ tăng max_tokens ở lượt sau: stop_reason là end_turn nên phản hồi không bị cắt, nguyên nhân nằm ở context

  • Liệt kê lệnh cấm trong CLAUDE.md: chỉ là hướng dẫn, duyệt nhầm hay mode rộng vẫn để lệnh chạy
  • Tắt log cho lệnh bị chặn: mất audit trail; dữ liệu nhạy cảm có thể redact thay vì bỏ cả bản ghi

  • XSS và SQL injection là danh sách đầy đủ: đồng nghiệp đã phủ tấn công web truyền thống, câu hỏi là Claude bổ sung rủi ro gì
