1. Kiến trúc agent, subagent & Agent SDK

  • Giao việc subagent: subagent chỉ nhận chuỗi prompt → ghi rõ phạm vi, định dạng, tiêu chí xong → "worker tự quyết khi nào xong" Q1
  • Manager review: manager đối chiếu các phần và quy tắc trích dẫn trước tổng hợp, trả lại phần lỗi (evaluator-optimizer) → "phần mâu thuẫn" Q1
  • Harness SDK: đăng ký tool qua SDK (MCP server in-process), để SDK lo loop, dispatch, permission, session → "đã chọn Agent SDK" Q2
  • System prompt SDK: preset claude_code + append ≠ chuỗi systemPrompt (thay thế hoàn toàn) ≠ không truyền (prompt tối giản) Q6
  • Cap subagent: giới hạn do SDK thực thi ≠ prompt xin: depth/concurrency qua env, spend cap tính cả subagent → "chi phí run vượt dự kiến" Q8, Q1
  • SessionStore: transcript mặc định ở đĩa cục bộ; gắn adapter ra kho bền vững rồi resume bằng session ID → "container bị thay khi deploy" Q7
  • Kết quả đã xác minh: lưu database ngoài kèm metadata nguồn, nạp đúng bản ghi; không dựa memory nháp hay compaction Q7
  • Tự host Agent SDK: runtime, shell, file phải ở Azure công ty → host harness trong Azure, vẫn gọi endpoint Claude; mã hóa không thay vị trí Q5
  • Nhận diện: "đã chọn Agent SDK" → dùng tính năng có sẵn (preset, SessionStore, outputFormat, cap); "tự viết" hay "nhờ prompt" là bẫy Q2, Q4, Q6, Q7, Q8

2. Tool use & structured output

  • Structured output SDK: outputFormat/output_format type json_schema, đọc structured_output; thiếu nó hoặc error_max_structured_output_retries là thất bại → "parser gãy" Q4
  • Kiểu TypeScript: Claude chỉ thấy input_schema → khai báo required integer, vẫn kiểm count ≥ 1 ở executor Q22
  • Cấu trúc ≠ đúng: refusal, cắt max_tokens vẫn lệch schema → kiểm stop_reason, validate, retry có giới hạn; không điền mặc định, không bỏ bản ghi Q42
  • Chọn tool: tên hướng hành động + mô tả chi tiết; nhiều tool thì tool search + defer_loading → "hàng chục tool, chọn nhầm" Q48
  • Lỗi tool: trả tool_result is_error: true, không đổi lỗi thành danh sách rỗng → "timeout mà trả lời không có" Q49
  • input_examples: ví dụ input cho object lồng, định dạng khắt khe; sai schema → lỗi 400; không dùng cho server tool Q50
  • Nguồn chính thống: web search server-side + allowed_domains (lọc tất định, có citation); web fetch không tìm kiếm → "chỉ nguồn cơ quan" Q53
  • Công thức tool: schema chặt + mô tả rõ + ví dụ hợp lệ + is_error + validate executor; nới schema gần như luôn sai Q22, Q48, Q49, Q50

5. Messages API & SDK chính thức

  • Stateless: mỗi request chứa toàn bộ hội thoại → app tự lưu, dựng lại user/assistant, tách theo hồ sơ → "API nhớ lượt trước" Q12
  • Quy ước cho bot API: CLAUDE.md chỉ của Claude Code → đặt quy ước vào trường system cấp cao nhất, test diff mẫu Q20
  • SDK chính thức: gom helper HTTP về một module dùng SDK TypeScript, pin phiên bản đã test, nâng cấp có chủ đích Q19
  • Debug SDK: logLevel/ANTHROPIC_LOG xem request thật, so với REST; SDK không chèn chỉ dẫn ẩn Q32
  • Proxy đi ra: fetchOptions (Node undici ProxyAgent, Bun proxy); baseURL không phải forward proxy Q35
  • Null vs vắng: Python SDK dùng model_fields_set phân biệt field trả null với field vắng mặt Q34
  • Hủy batch: canceling → poll tới ended, giữ kết quả succeeded, gửi lại phần bị hủy Q33
  • stop_reason: max_tokens và model_context_window_exceeded là output dang dở; system, tool, history đều tính input Q29
  • Prefill: từ Claude 4.6 trả lỗi 400 → chuyển thành chỉ dẫn trong system prompt Q40

6. Quản lý context, tài liệu & prompt caching

  • Cache prefix: chỉ khớp tuyệt đối → phần đổi (timestamp) ra sau phần ổn định, breakpoint, kiểm cache_read_input_tokens → "cache read gần 0" Q31
  • Cache không giữ tool: request nào cũng gửi lại tool; cache đã phân vùng theo organization Q31
  • Prune tool result: context editing xóa kết quả tool cũ, giữ lần gần nhất, loại trừ log_finding; hồ sơ đủ ở kho audit Q39
  • Caching ≠ giải phóng context: giảm tiền, không giảm chỗ trong window Q39
  • Nhiều khách: mỗi tài khoản một history riêng, đổi khách thì message list mới → "chi tiết khách trước lọt sang" Q23
  • PDF dài: ≤ 600 trang/request, mỗi trang tính text + ảnh → cắt chương, upload Files API, gửi file_id chương cần Q14
  • Compaction có mất mát: rơi số liệu, trích dẫn, không xóa chính xác dữ liệu một khách Q7, Q23, Q38

  • Output xác suất: khác chữ ≠ request sai; temperature khác mặc định lỗi 400 từ 4.7, cũng không đảm bảo giống hệt Q30
  • Eval: chỉnh nhóm yếu, đo bằng capability eval + regression eval (~100%) rồi lặp Q41
  • Test tập trung: mỗi bước có tiêu chí thành công cụ thể Q18, Q41

8. Model, chi phí, rate limit & yêu cầu hạ tầng

  • Advisor tool: executor Sonnet tự hỏi model mạnh hơn khi gặp ca khó; đo trên eval riêng → "chỉ ca khó cần suy luận sâu" Q36

  • Vị trí inference: tham số inference_geo: "us" + trường usage làm audit ≠ dặn trong prompt Q9

9. Bảo mật, guardrails & human-in-the-loop

  • Cổng duyệt: PreToolUse hook trả defer ≠ lời dặn; thoát với tool_deferred, resume khi duyệt → "chờ duyệt hàng giờ" Q3
  • Least privilege: chỉ cấp tool thường ngày; tool không có thì không gọi được dù bị injection Q3
  • Nội dung ngoài: trả dưới dạng tool result ghi nguồn, không nhét vào system prompt Q21
  • Web không tin cậy: proxy ngoài boundary chèn API key + allowlist endpoint + log; key không vào context Q44
  • PHI dưới BAA: chỉ message và file được bảo vệ; schema cache riêng → không đặt PHI trong enum/const/pattern Q45
  • Credential môi trường: mỗi môi trường một key, workspace riêng, secrets manager phân quyền theo workload Q46
  • Key trong app di động: coi như lộ → thu hồi, chuyển gọi Claude về backend, key mới vào managed secrets Q47
  • Thẩm quyền: từ hệ thống xác thực, không từ giá trị model cung cấp Q21

Học đáp án đúng chỉ giải được đúng câu đó. Hiểu vì sao từng đáp án sai lại sai giúp nhận diện được cả họ câu hỏi tương tự, kể cả khi đề đổi cách hỏi. Mỗi dòng dưới đây là một câu, liệt kê các đáp án sai và lý do sai thật sự — đúc kết từ chính phần giải thích của đề, không phải suy đoán.
