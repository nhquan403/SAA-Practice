Cách đọc đề — theo đúng thứ tự nên làm

  1. Thực thi hay chỉ là lời dặn? Đề có must not depend on, guarantee, even if → chọn hook, schema, allowlist, role; loại lời dặn trong prompt.
  2. Đọc tín hiệu trong JSON/code. stop_reason, usage, mã HTTP, error message thường đủ gạch 2–3 đáp án.
  3. "Làm gì trước tiên?" = thu thập bằng chứng. Xem trace, debug log, usage, làm rõ tiêu chí trước khi đổi model hay framework.
  4. "Lớn hơn" hiếm khi đúng. Tăng max_tokens chỉ đúng khi stop_reason là max_tokens; suy luận sâu thật → advisor tool hoặc effort.
  5. Mỗi cơ chế giải một vấn đề. Streaming = thời điểm, structured output = hình dạng, caching = chi phí input, compaction/subagent = nhiễu.
  6. "Select two" là hai nửa bổ trợ. Strict + JSON outputs, cache + batch, plan mode + acceptEdits, null + đối chiếu nguồn.
  7. Phòng ngừa thắng phát hiện. Review sau, quét đêm, cảnh báo CI, Stop/PostToolUse hook đều quá muộn khi đề đòi "trước khi".
  8. Ưu tiên đáp án có bước đo. "Chạy lại eval", "so baseline", "nhiều trial" thường đúng; "ship ngay", benchmark công khai, tự chấm thường sai.
  9. Bám công cụ đề đã chọn. Đã có Agent SDK hay SDK chính thức thì dùng tính năng có sẵn, không tự viết lại.
  10. Đúng chỗ đặt. Kiến thức → CLAUDE.md; quy trình thưa → skill; quyền → settings; cưỡng chế → hook; hệ thống ngoài → MCP; credential → secrets manager.
  11. Ít dữ liệu là an toàn hơn. Không gửi thứ không cần; loại đáp án đổi lỗi thành rỗng, điền mặc định, lặng lẽ bỏ bản ghi.
  12. Loại đáp án xây cho tương lai giả định. Bám ưu tiên đề nêu: "chờ được" → batch, "một giây" → không batch, người không code → không terminal.
  13. Tên model/tham số cụ thể là có chi tiết riêng. Nhớ effort mặc định, tham số bị loại (prefill, temperature) và tham số bịa (parallel_tool_calls).
  14. Giữ context thay vì tóm tắt sang session mới. Đổi mode trong session, fork, hoặc ghi trạng thái ra git/file tiến độ/CLAUDE.md.

ZDR — Zero Data Retention. Không lưu dữ liệu; xét theo từng tính năng.
PII — Personally Identifiable Information. Dữ liệu định danh cá nhân cần redact trước khi gửi.
PHI — Protected Health Information. Thông tin sức khỏe định danh được, được HIPAA bảo vệ.
HIPAA — Health Insurance Portability and Accountability Act. Luật Mỹ về bảo vệ dữ liệu y tế.
BAA — Business Associate Agreement. Thỏa thuận cho phép xử lý PHI theo HIPAA.
OAuth — Open Authorization. Chuẩn ủy quyền cấp access token có scope và thời hạn.
Audience — Claim trong token cho biết token được cấp cho dịch vụ nào.
Token passthrough — Chuyển tiếp token của client xuống dịch vụ khác; bị spec MCP cấm.
Confused deputy — Dịch vụ có quyền bị lừa làm thay bên không quyền.
DNS rebinding — Tấn công MCP chặn bằng validate header Origin.
BOLA — Broken Object Level Authorization. Thiếu kiểm quyền trên từng đối tượng.
OWASP — Open Worldwide Application Security Project. Danh sách rủi ro bảo mật; LLM02:2025 = lộ thông tin nhạy cảm.
KMS — Key Management System. Hệ thống quản lý khóa/secret, được khuyên dùng cho API key.
XSS / SQL injection — Cross-Site Scripting / Structured Query Language. Lỗ hổng web truyền thống, không riêng LLM.
Đánh giá, vận hành & khác (24 mục)
Eval — Evaluation. Bộ case và cách chấm để đo chất lượng.
Held-out set — Tập để riêng, chỉ dùng để đánh giá.
Baseline — Kết quả chuẩn để so, thường từ version trước.
Capability / regression eval — Đo phần cần cải thiện / bảo vệ hành vi tốt (~100%).
Rubric — Tiêu chí chấm điểm dùng chung cho offline và production.
Trial — Một lần chạy một case; nhiều trial để đo tỉ lệ.
Table-driven test — Test lặp qua bảng đầu vào và kết quả mong đợi.
A/B testing / shadow mode — So hai bản trên traffic thật / chạy song song chỉ log.
TDD / E2E — Test-Driven Development / End-to-End. Viết test trước code / test trọn hành trình.
SLO — Service-Level Objective. Mục tiêu vận hành: latency, availability, failover.
TTFT — Time To First Token. Thời gian tới token đầu tiên.
OTPS — Output Tokens Per Second. Tốc độ sinh output token; fast mode tăng chỉ số này.
p95 — 95th percentile. 95% request nhanh hơn mức này; tốt hơn trung bình.
RPM / ITPM / OTPM — Requests / Input Tokens / Output Tokens Per Minute. Ba chiều rate limit; ITPM thường chỉ tính input chưa cache.
Acceleration limits — Giới hạn khi mức dùng tăng đột ngột, gây 429.
Backoff — Exponential backoff. Chờ lâu dần giữa các lần retry.
Circuit breaker — Ngắt gọi sau nhiều lỗi liên tiếp, trả fallback.
Backpressure — Làm producer chậm lại theo tốc độ consumer.
Server-side fallback — Bị refuse thì API chuyển model trong cùng request.
Deprecation — Báo ngừng hỗ trợ kèm thời hạn và lộ trình.
CRM — Customer Relationship Management. Hệ thống quản lý khách hàng mà agent tra cứu.
CSV — Comma-Separated Values. Định dạng bảng văn bản, đọc theo vị trí cột.
SaaS — Software as a Service. Phần mềm dạng dịch vụ cho nhiều khách (multi-tenant).
RAM — Random Access Memory. Bộ nhớ tạm — nơi MemorySaver giữ checkpoint, mất khi restart.
