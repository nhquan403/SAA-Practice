Lỗi, retry, rate limit & truy vết

Đọc error type và message trước khi sửa code: lỗi tạm thời (429/529) để SDK retry, lỗi request (400) thì retry vô ích — và luôn giữ request ID.

Cách đọc đề — theo đúng thứ tự nên làm

  1. Hỏi "cái này được thực thi ở đâu, hay chỉ là lời dặn?" Đề có chữ must not depend on, never, guarantee, enforce, even if, before money moves thì loại mọi đáp án chỉ là lời dặn trong system prompt, CLAUDE.md, tool description hay một model reviewer khác. Đáp án đúng gần như luôn là code hoặc cấu hình: hook, schema, allowlist, danh sách tool, role, phân tách dữ liệu.
  2. Đọc tín hiệu trong JSON/code của đề. stop_reason, khối usage, mã HTTP, error message, vòng while True chỉ thoát ở end_turn — chi tiết nhỏ này thường đủ gạch 2–3 đáp án. Mã HTTP giống nhau có thể có nguyên nhân khác nhau; message thường nêu thẳng nguyên nhân.
  3. "Làm gì trước tiên?" thường là thu thập bằng chứng. Xem request/trace thật, đọc debug log, ghi usage theo tính năng, làm rõ tiêu chí — trước khi đổi framework, viết lại hook, đổi model hay tham số.
  4. "Lớn hơn" hiếm khi là đáp án. Context window lớn hơn, max_tokens cao hơn, model mạnh hơn, chỉ dẫn dài hơn, viết hoa to hơn đều chỉ hoãn hoặc che vấn đề. Đáp án "tăng max_tokens" chỉ đúng khi stop_reason là max_tokens; ngoại lệ cho "model mạnh hơn" là chỗ cần suy luận sâu thật — và khi đó thường là advisor tool hoặc effort.
  5. Mỗi cơ chế giải đúng một vấn đề. Streaming lo thời điểm, structured output lo hình dạng, caching lo chi phí input, compaction/clearing/subagent lo nhiễu, max_tokens lo độ dài output. Đáp án sai thường mượn một cơ chế để giải vấn đề của cơ chế khác (hỏi "mất tập trung" mà đáp án là caching).
  6. Câu "Select two" thường là hai nửa bổ trợ nhau. Strict tool use + JSON outputs; cache + batch; server tool + client tool; plan mode + đổi sang acceptEdits; cho phép null + đối chiếu hệ thống thật; giữ file_id phía server + tách workspace; proxy chèn key + allowlist; output style + CLAUDE.md. Thường là ngăn chặn + kiểm chứng, input + output, tự động + phê duyệt người.
  7. Phòng ngừa thắng phát hiện sau. Review sau, batch quét đêm, cảnh báo CI, version history, Stop/PostToolUse hook, audit sau xuất bản đều là "phát hiện quá muộn". Đề đòi "trước khi" thì loại hết.
  8. Eval trước, ship sau — và ưu tiên đáp án có bước đo lường. Đáp án đúng thường kèm "chạy lại bộ eval", "so với baseline", "nhiều trial", "regression eval", "xác nhận trong usage data". Đáp án "ship ngay", "dựa vào benchmark công khai", hay model tự chấm điểm thường sai.
  9. Đề đã nói team chọn công cụ gì thì bám vào công cụ đó. Đã chọn Agent SDK thì dùng harness, preset, SessionStore, outputFormat của SDK; đã có SDK chính thức thì dùng retry, helper, debug logging, fetchOptions thay vì viết tay HTTP. Tự viết lại thứ Anthropic đã cung cấp thường là đáp án nhiễu.
  10. Chọn đúng nơi đặt thứ gì. Kiến thức dự án → CLAUDE.md; quy trình dùng thưa → skill; mọi phản hồi → output style; quyền → settings/permission rule; cưỡng chế → hook; dữ liệu sống, hệ thống ngoài → MCP; cô lập context → subagent; dữ liệu bên thứ ba → tool_result; credential → secrets manager. Phân biệt luôn Claude Code (CLAUDE.md, rules, plugin, worktree) với Messages API thô (chỉ có những gì ứng dụng gửi).
  11. Ít dữ liệu hơn là an toàn hơn; loại đáp án đổi ý nghĩa dữ liệu để hệ thống "chạy tiếp". Giảm rủi ro rò rỉ = không gửi/không lưu thứ không cần, không phải mã hóa hay dặn model. Đổi lỗi thành danh sách rỗng, điền mặc định, lặng lẽ bỏ bản ghi đều giữ hệ thống sống nhưng làm kết quả sai.
  12. Loại đáp án xây cho tương lai giả định, và bám thứ tự ưu tiên đề nêu. "Sau này có thể phức tạp hơn" là lý do thêm độ phức tạp chưa chứng minh. "Chi phí là chính, chờ được" → batch; "phản hồi trong một giây" → không batch; "chưa xếp hạng ưu tiên" → định nghĩa tiêu chí trước. Đọc kỹ ai là người dùng: người không viết code thì không đưa terminal.
  13. Đề nhắc tên model cụ thể hay tham số cụ thể là có chi tiết riêng. Opus 5.5/Haiku 5.5/Sonnet 5.5: effort mặc định, long context pricing, adaptive thinking, forced tool use. Để ý tham số đã bị loại trên model mới (prefill, temperature, thinking.type: "enabled") và tham số bịa nghe hợp lý (parallel_tool_calls top-level).
  14. Giữ nguyên context thay vì tóm tắt rồi mở session mới. Đáp án "dán tóm tắt ngắn vào session mới" luôn mất chi tiết; đáp án đúng thường là đổi mode trong cùng session, fork, hoặc ghi trạng thái ra git/file tiến độ/CLAUDE.md.

Allowlist — Danh sách đích được phép; mọi đích khác bị chặn.
Harmlessness screen — Model nhẹ sàng lọc input trước khi vào hội thoại chính.
Fail closed — Khi thành phần bảo vệ lỗi thì chặn, không cho đi qua.
ZDR — Zero Data Retention. Thỏa thuận không lưu dữ liệu; đủ điều kiện xét theo từng tính năng.
PII — Personally Identifiable Information. Dữ liệu định danh cá nhân cần redact trước khi gửi.
PHI — Protected Health Information. Thông tin sức khỏe định danh được, được HIPAA bảo vệ.
HIPAA — Health Insurance Portability and Accountability Act. Luật Mỹ về bảo vệ dữ liệu y tế.
BAA — Business Associate Agreement. Thỏa thuận cho phép nhà cung cấp xử lý PHI theo HIPAA.
OAuth — Open Authorization. Chuẩn ủy quyền cấp access token có scope và thời hạn.
Audience — Claim trong token cho biết token được cấp cho dịch vụ nào.
Token passthrough — Chuyển tiếp token của client xuống dịch vụ khác; bị spec MCP cấm.
Confused deputy — Dịch vụ có quyền bị lừa hành động thay cho bên không có quyền.
DNS rebinding — Kiểu tấn công mà spec MCP yêu cầu chống bằng cách validate header Origin.
BOLA — Broken Object Level Authorization. Thiếu kiểm tra quyền trên từng đối tượng (đơn hàng của người khác).
OWASP — Open Worldwide Application Security Project. Tổ chức công bố danh sách rủi ro bảo mật, có bảng riêng cho ứng dụng LLM (LLM02:2025 = lộ thông tin nhạy cảm).
KMS — Key Management System. Hệ thống quản lý khóa/secret, được khuyên dùng cho API key.
XSS / SQL injection — Cross-Site Scripting / Structured Query Language. Lỗ hổng web truyền thống, không phải rủi ro riêng của LLM.
Đánh giá, vận hành & khác (24 mục)
Eval — Evaluation. Bộ case và cách chấm để đo chất lượng output của model/prompt.
Held-out set — Tập dữ liệu để riêng, không dùng khi phát triển, chỉ để đánh giá.
Baseline — Kết quả chuẩn để so sánh, thường từ hệ thống hoặc version trước.
Capability / regression eval — Đo phần còn yếu cần cải thiện / bảo vệ hành vi đang tốt, kỳ vọng gần 100%.
Rubric — Tiêu chí chấm điểm dùng chung cho offline và production.
Trial — Một lần chạy của một case; chạy nhiều trial để đo tỉ lệ.
Table-driven test — Test lặp qua bảng đầu vào và kết quả mong đợi.
A/B testing / shadow mode — So hai phiên bản trên traffic thật / chạy bản mới song song chỉ ghi log.
TDD / E2E — Test-Driven Development / End-to-End. Viết test trước code / test hành trình trọn vẹn qua toàn hệ thống.
SLO — Service-Level Objective. Mục tiêu vận hành: latency, availability, failover.
TTFT — Time To First Token. Thời gian tới token đầu tiên — chỉ số "cảm giác nhanh".
OTPS — Output Tokens Per Second. Tốc độ sinh token output; fast mode cải thiện chỉ số này.
p95 — 95th percentile. 95% request nhanh hơn mức này; tốt hơn trung bình để đặt giới hạn latency.
RPM / ITPM / OTPM — Requests / Input Tokens / Output Tokens Per Minute. Ba loại rate limit; đa số model chỉ tính input chưa cache vào ITPM.
Acceleration limits — Giới hạn khi mức dùng tăng đột ngột, gây 429.
Backoff — Exponential backoff. Chờ lâu dần giữa các lần retry.
Circuit breaker — Ngắt gọi dịch vụ sau nhiều lỗi liên tiếp, trả fallback, thử lại sau.
Backpressure — Làm producer chậm lại theo tốc độ consumer.
Server-side fallback — Khi bị refuse, API tự chuyển sang model khác trong cùng request.
Deprecation — Thông báo ngừng hỗ trợ kèm thời hạn và lộ trình di chuyển.
CRM — Customer Relationship Management. Hệ thống quản lý khách hàng mà agent tra cứu.
CSV — Comma-Separated Values. Định dạng bảng văn bản, đọc theo vị trí cột.
SaaS — Software as a Service. Phần mềm dạng dịch vụ cho nhiều khách (multi-tenant).
RAM — Random Access Memory. Bộ nhớ tạm — nơi MemorySaver giữ checkpoint, mất khi restart.
